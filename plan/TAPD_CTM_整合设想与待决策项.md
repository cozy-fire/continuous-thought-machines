# TAPD 与 CTM 整合：设想梳理与待决策项

**整体可行，但这次整合会同时改变 CTM 的输入方式、Maze 的训练目标，以及 TAPD 的知识迁移接口。** 最需要先明确的是：**知识库保留哪些模块、视觉 backbone 如何复用、循环状态如何参与蒸馏。**

下面只做设想梳理和待决策项，不作为实施计划。你刚才已经确定：

- Maze 保留全图观察；4Rooms 保留原来的局部视野和遮挡。
- 网络只接收像素，不额外输入任务 ID。
- 两个任务均使用 PPO-clip、Actor–Critic 和跨环境步保留的 CTM 历史，同时保留 Attention。
- 首轮 Maze 使用 `mazes-medium`。

## 一、输入输出统一：维度可以统一，但任务含义仍有差别

你的动作方案可以成立：

| 策略输出 | Maze | 4Rooms |
|---|---|---|
| 0 | 上 | 左转 |
| 1 | 下 | 右转 |
| 2 | 左 | 前进 |
| 3 | 右 | 等待 |
| 4 | 等待 | 等待 |

这里有两个需要明确的事实。

第一，TAPD 原映射的输出槽对应统一的 `NOOP/FIRE/RIGHT/LEFT`；当前方案统一了**输出维数**，但没有统一动作语义。例如，输出 0 的含义依赖环境。它仍然可行，只是策略需要通过像素和历史识别环境，再决定动作。这会让迁移问题同时包含“识别环境”和“适应控制方式”。见 [TAPD 动作映射](/D:/CodeProject/TAPD/src/envs.py:54)。

第二，**MiniGrid 的 `step(9)` 会报错**。本地已实测：可以把 9 保留为适配层内部的等待标记，再执行真正的等待行为；策略和好奇心预测器仍使用 `0…4`，不能把 9 送入五维 one-hot。两个等待槽不屏蔽时，均匀策略有 40% 的概率等待，这是这个映射自然带来的探索偏置。

输入方面还有这些待定项：

| 待决策项 | 选项及影响 |
|---|---|
| 图像尺寸 | 例如统一到 `84×84` 或 `112×112`；前者计算较省，后者保留更多细节。 |
| 渲染风格 | 保留两种环境原来的颜色、形状，或者统一墙、道路、目标、agent 的画法。前者更接近跨视觉域迁移，后者更容易共享视觉特征。 |
| ResNet 规格 | ResNet18/34、截取到哪个 stage、随机初始化还是 ImageNet 初始化。仅指定“ResNet”还不足以确定实际模型。 |
| 时间输入 | 建议暂用单帧 RGB，由 CTM 负责历史记忆；是否额外堆帧需要明确。 |
| 空间位置编码 | 两种输入都有空间结构，但一个是全局坐标，一个是随朝向变化的局部坐标。是否给 Attention 加二维位置编码尚未确定。 |

统一尺寸不会统一观察难度：Maze 能直接看到目标和全图；4Rooms 仍需要记忆与探索。这个差异与你确认的视野设置一致。

## 二、带 Attention 的 RL CTM：梯度路径合理，但时间定义要统一

建议讨论的计算结构是：

```text
当前 RGB → ResNet 空间特征 → K、V
                               ↓
历史激活 → S_action → Q → Attention
                               ↓
                 与当前激活状态拼接
                               ↓
                      Synapse → NLM
                               ↓
                     更新预激活/激活历史
                               ↓
               最后一个 tick 的 S_out
                               ↓
                    Actor、Critic
```

PPO 和价值损失可以沿下面的路径反传：

$$
L_{\mathrm{PPO}},L_V
\rightarrow S_{\mathrm{out}}
\rightarrow \mathrm{NLM}
\rightarrow \mathrm{Synapse}
\rightarrow \mathrm{Attention}
$$

Attention 再分出两条路径：

- 经 $K,V$ 回到视觉 backbone；
- 经 $Q$ 回到 $S_{\mathrm{action}}$ 和更早的激活历史。

因此，**保留 Attention 本身没有梯度上的障碍**。动作采样与环境转移不需要可微，PPO 通过动作的 log-probability 更新策略。

现有 CTM RL 训练已经按时间顺序重放 rollout，能够沿多个环境步反传；这一点适合保留。见 [PPO 序列重放](/D:/CodeProject/continuous-thought-machines/tasks/rl/train.py:500)。

需要你决定的是：

| 待决策项 | 我的倾向 |
|---|---|
| $S_{\mathrm{action}}$ 是否也使用滑动窗口 | **使用**，与 RL 的 $S_{\mathrm{out}}$ 保持一致，但两者有独立衰减参数。 |
| 每个环境步执行几个 tick | 两任务先用相同数量；具体取 1、2 或更多，需要结合记忆与算力目标决定。 |
| NLM 历史和同步性历史是否同长 | 首轮共用 $M$，减少独立变量。 |
| 是否监督中间 tick | 首轮只在最后一个 tick 输出动作/value，不额外引入中间监督。 |
| 状态何时重置 | episode 结束及任务切换时重置；正常环境步之间保留。 |
| 跨多少环境步反传 | 由 rollout/截断反传长度确定，不能与历史窗口 $M$ 混为一谈。 |

特别注意：**$M$ 的单位是内部 tick，不是环境步。** 每步执行更多 tick，会改变历史窗口实际覆盖的环境时间。

## 三、知识库保留范围：我倾向先保留完整策略计算链

| 方案 | 优点 | 主要问题 |
|---|---|---|
| **完整双列**：各自保留 ResNet、Attention、CTM、同步性读出和 Actor | KB 是可以独立运行的完整策略；策略蒸馏和遗忘评估有明确对象 | 计算和显存较高，需要处理视觉特征的保护与迁移 |
| **固定共享 ResNet＋完整双列控制器** | 减少视觉重复计算，KB 接收的特征坐标稳定 | 固定后不能继续适应新视觉域；必须决定何时冻结 |
| **仅保留 Synapse/NLM，其余随任务重训** | 保留模块较少，任务适应更自由 | 编码器、Attention 和输出头变化后，保留的核心可能失去原有输入与输出含义 |

第三种方案的问题不只是“忘得更多”，而是：

$$
\text{同一组核心参数}
+\text{新的输入表示}
+\text{新的读出方式}
\quad\not\Rightarrow\quad
\text{同一个已学会的技能}
$$

而且只保存 Synapse/NLM，还没有规定 CTM 的初始历史、同步衰减参数、神经元配对等参数如何处理。

**我的建议是先把完整策略计算链作为 KB。** “仅保留核心”可以作为后续研究方案，但它需要重新定义迁移目标，不能直接套用原 TAPD 的完整策略 KL 蒸馏。

除此之外，双列结构还有三个独立决策：

1. **侧向连接接在哪里？**  
   接在同步性表示/Actor 前，结构简单；接在每个 tick 的 Synapse 输入或内部状态上，能直接影响思考过程，但耦合更强。二者是不同的研究设计。

2. **是否保留、蒸馏 Critic？**  
   TAPD 当前只蒸馏动作分布，KL 不会训练 KB 的 value head。尤其从内在奖励切换到外在奖励后，旧 value 的含义已经变化。我的倾向是优先明确 Actor 的知识保留，Critic 按当前奖励目标学习。

3. **Active 换任务时重置什么？**  
   是完整重置、只重置控制器和头，还是从 KB 初始化？对于希望复用的视觉 backbone，这个决定尤其关键。

## 四、“复用 φ_agnostic”至少有三种不同含义

| 复用方式 | 含义 | 需要承担的代价 |
|---|---|---|
| **复制预训练权重** | 后续策略用它初始化，各列拥有独立参数 | 不会相互直接干扰，但视觉表示随后会分化 |
| **从一开始实时共享** | 策略与好奇心模块使用同一个 ResNet，接受两种损失 | 要处理损失权重、更新频率，以及共享更新对 KB 的影响 |
| **预训练后固定共享** | 后续各列使用同一个冻结的 ResNet | 视觉表示稳定，但后续视觉适应受限 |

这里存在一个必须正面处理的冲突：

> 如果 Active、好奇心模块和 KB 使用同一个持续更新的 backbone，冻结 KB 的其余参数，也不能保证 KB 的策略保持不变。

因为 KB 收到的特征已经变了。仅在 task-agnostic 结束后冻结，也不能消除前面阶段已经发生的这种变化。

另一种需要避免的做法是：**先独立训练好 KB，再把它的 backbone 硬替换成 $\phi_{\text{agnostic}}$**。两套特征没有自动对齐，替换可能破坏 KB 已学会的控制策略。

因此，“复用视觉”需要一起决定：

- 从什么时候开始复用？
- 是同一个参数对象，还是复制权重？
- PPO、预测损失、蒸馏损失分别更新哪些模块？
- 后续 P&C 是否继续训练好奇心模型？
- Active 重置时，视觉参数如何保留？

关于好奇心公式，本地 TAPD 实际使用：

$$
L_{\mathrm{fwd}}
=\left\|\mathcal F(\phi(s_t),a_t)-\phi(s_{t+1})\right\|_2,
\qquad
r_t^i=\log(1+L_{\mathrm{fwd}})
$$

奖励会 `detach`，但预测目标一侧的 $\phi(s_{t+1})$ 没有 stop-gradient；编码器两端都会被更新。论文写的是平方范数与 $\log(L+\epsilon)$，存在代码/论文口径差异。见 [实际奖励计算](/D:/CodeProject/TAPD/src/progress_compress_agnostic.py:321) 和 [论文公式](https://arxiv.org/html/2411.16532v1#S4.SS3)。

**待决策：**

- “保持 TAPD 一致”以代码公式还是论文公式为准？
- 预测 ResNet 的空间特征图，还是池化后的向量？是否保留固定维数的投影头？
- 是否保持两端同时反传，还是引入 stop-gradient/固定目标？
- 共享视觉后，预测损失与 PPO 损失怎样平衡？

最后一项不能省略：从目标函数上看，若编码器和预测器都输出常量，预测误差也能降低。这说明**低预测误差本身不能保证学到适合控制的视觉特征**；这不是说当前训练已经塌缩，而是复用该编码器时需要验证的性质。

## 五、Maze 改为 RL：奖励与 episode 定义还需要明确

先纠正一个前提：**4Rooms 原生不是每步扣分**，而是成功时获得

$$
r_{\mathrm{success}}=1-0.9\,t/H
$$

其余普通步骤奖励为 0。[官方奖励说明](https://minigrid.farama.org/environments/minigrid/FourRoomsEnv/)

因此下面两个方案不同：

- **沿用 4Rooms**：普通步 0，成功奖励随耗时降低。
- **显式步惩罚**：每步 $-c$，成功时增加奖励，超时另行定义。

| 待决策项 | 选项及我的倾向 |
|---|---|
| 奖励方案 | 若优先对齐原 4Rooms，选第一种；若明确希望每步扣分，则需要同时决定两任务是否都改。 |
| 最大步数 | 可先统一为 300；也可以 Maze 单独设置，但两者难度与奖励尺度会变化。 |
| Maze 起终点 | 沿用数据中的起终点，或每个 episode 重新采样。首轮倾向沿用。 |
| Maze 撞墙/越界 | 倾向原地不动、消耗一步；是否额外惩罚需要明确。 |
| 任务无关阶段的目标终止 | 到达目标仍结束，还是允许继续探索？取消终止会改变原环境过程。 |
| 超时处理 | 应区分真正终止与时间上限；是否进行 value bootstrap 要明确。 |

Maze 的观察必须随 agent 移动更新。现有 PNG 中蓝色部分是**答案路径**，原数据集会先擦掉再输入模型，新 RL 环境也必须保留这一处理。见 [数据预处理](/D:/CodeProject/continuous-thought-machines/data/custom_datasets.py:324)。

## 六、训练调度：“与 TAPD 一致”需要指定参考配置

本地 [full 配置](/D:/CodeProject/TAPD/config/tapd_progress_and_compress.yml:17) 的预算是：

| 阶段 | 步数 |
|---|---:|
| Task-agnostic 抽样次数 | 5 次 |
| 每次探索 | 300,000 |
| 每次探索后的 Compress | 300,000 |
| 每任务每 visit 的 Progress | 2,500,000 |
| 每任务每 visit 的 Compress | 1,000,000 |
| visit 次数 | 3 |

用于两个任务时，名义预算是 **3M 预训练阶段交互＋21M 后续 P&C 交互＝24M**，另有 Fisher 采样和评估。本地还有减半预算配置，因此需要指定沿用哪一份。

这里的步数是**所有并行环境的 transition 总数**，不是 PPO 更新次数，也不是 CTM tick 数。换成 ResNet 和循环双列后，同样的环境步数不会对应同样的计算成本。

调度方面尚有这些问题：

- **Task-agnostic 是否保证覆盖两个任务？** 原代码均匀有放回抽样 5 次，有 6.25% 的概率只抽到一个任务。我的倾向是保证两个任务都出现。
- **后续任务顺序是什么？** 固定 Maze → 4Rooms，还是随机顺序？
- **探索阶段切换任务时是否重置 Active？** 原代码在整个任务无关阶段开始时重置一次，抽样切换间持续训练；后续 P&C 则每任务每 visit 重置。
- **重置模型时是否同时重置优化器？** 原代码没有同步清空优化器历史，不能不加区分地照搬到 PPO。
- **迁移哪些超参数？** 步数和 visits 可以参考 TAPD，但 TAPD 原优化器是 A2C；PPO 的学习率、clip、rollout 长度、更新 epoch、熵系数需要另定。

## 七、循环蒸馏与 EWC：有两处不能直接照抄 TAPD

**循环蒸馏必须保留历史。** KB、Active、蒸馏教师和学生需要分别维护自己的 CTM 状态，并沿同一段观测历史推进。不能把 Active 的 hidden state 直接交给 KB，也不能像前馈策略那样随机打散单帧后蒸馏。

待定项包括：

- 蒸馏数据由教师还是学生采样？倾向先沿用 TAPD 的教师采样。
- 蒸馏序列多长，序列开始是否需要一段历史预热？
- 只蒸馏最终动作分布，还是增加 value/内部表示约束？倾向首轮只保留必要的动作 KL。
- EWC 保护完整策略，还是只保护部分核心？
- KB 的冻结是否包括 BatchNorm 的运行统计？**需要包括**，否则参数不变也可能改变策略。

另一个实质问题是：当前 TAPD 的 `gather_fisher_samples` 会使用环境返回的外在奖励构造 advantage，任务无关阶段也走这条路径。见 [Fisher 采样](/D:/CodeProject/TAPD/src/algo/a2c.py:390)。

因此必须二选一：

- 严格保持任务无关阶段不利用外在奖励，采用不依赖奖励的策略 Fisher；
- 复刻当前代码中的奖励相关重要性估计，并明确它不满足严格的“无外在奖励”。

我倾向第一种，但它属于有意识地修改 TAPD 实现。

## 八、怎样判断整合有效，也需要提前确定

如果任务无关阶段已经探索过 Maze 和 4Rooms，后续实验主要验证的是**预先探索过的任务域上的快速学习与知识保持**；“未见任务迁移”需要另外留出任务，不能仅靠更换迷宫布局来宣称。

至少需要明确：

| 待决策项 | 建议 |
|---|---|
| 最终评估对象 | KB 独立策略作为知识保持对象，Active 单独用于评估适应速度。 |
| 指标 | 成功率、达到目标的步数、学习曲线，以及学完另一任务后的性能下降。 |
| 对照组 | 单任务 CTM、顺序 PPO CTM、无任务无关阶段的 P&C；是否本轮以后再增加视觉复用消融。 |
| 测试划分 | Maze 用独立测试地图，4Rooms 用独立固定测试 seeds。 |
| 随机性 | 训练 seed、任务采样 seed、环境 seed 分开记录；正式比较使用多少个 seed 尚未定。 |

本地数据还有一个已查明的事实：`medium/test` 根目录存在与训练集重叠的图片，因此不能递归合并所有 PNG；应沿用正式的 `train/0`、`test/0` 划分。这属于数据正确性要求，不需要作为偏好选择。

**我建议下一轮优先讨论三个决定：①完整双列还是部分核心；②视觉复用是复制权重、实时共享还是冻结共享；③奖励采用 4Rooms 原规则还是显式每步扣分。** 这三个决定会约束后面的梯度、重置、蒸馏和训练调度设计；其余参数可以随后逐项收敛。
